## P0 — fix

### C2 — `idl.json` must include `rootNamespace`
- `writeIDLJSONGo`: emit `rootNamespace` alongside `checksum`, `interfaces`,
  `structs`, `enums`, `errors`. Confirm `IDL_JSON` (marshalled `*parser.IDL`)
  also carries it and the same checksum.
- Add a generator test that unmarshals both forms and asserts the keys.

### R15 — do not leak handler errors
- `pkg/runtime/runtimes/go/pulserpc/server.go` line ~150: return
  `-32603, "Internal error"` with **no data**; `log.Printf` the error
  server-side (redact secrets). Keep `-32602` validation messages (they are
  user-facing and safe).
- Add a test: a handler returning `errors.New("secret-token")` produces no
  secret in `message`/`data`.

### R16 / R18 — generated server limits
- Generated test server: wrap the body with
  `http.MaxBytesReader(w, r.Body, 1<<20)` and return `-32600 "Request body too
  large"` on overflow.
- Batch: reject `len(requests) > 100` with `-32600 "Batch exceeds maximum
  size"`.
- Add generator tests asserting the constants/fragments and a live e2e check
  if practical.

### R20 — runtime client ids are atomic
- `pkg/runtime/runtimes/go/pulserpc/client.go`: replace `c.requestID++` with
  `atomic.AddUint64` (or a mutex); keep the generated client's atomic path.
- Add a concurrent test (`go test -race` optional) asserting distinct ids.

### R22 — non-POST shape
- Generated server currently returns 405. Add a JSON-RPC `-32600` body with
  `id:null` (D3) for non-POST. Update the generator test.

### R24 / R25 — id type and int range
- Server: reject a boolean/object/array `id` with `-32600`.
- `ValidateInt`: reject integral values outside signed 64-bit
  (`math.MinInt64`…`math.MaxInt64`), as well as fractional/NaN/Inf/bool.
  Update tests and any fixtures using large ints.

### M19 — non-object batch entries
- Generated batch loop currently skips non-map entries. Add a per-entry
  `-32600 "Invalid Request"` response and keep the array shape.
